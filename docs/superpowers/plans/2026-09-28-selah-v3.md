# Selah v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Leitura em voz alta no leitor, busca por palavra offline e destaques com anotações.

**Architecture:** Cada recurso tem um núcleo puro e testável (`speech.ts`, `search.ts`, e os registros de marcação em `storage/`), e as telas Svelte só ligam esse núcleo à interface. As marcações ganham um store próprio no IndexedDB (banco na versão 2) e entram no backup (versão 2, aceitando também a 1).

**Spec:** `docs/superpowers/specs/2026-09-28-selah-v3-voz-busca-marcacoes.md`

**Execução:** nativa, pelo próprio autor, que já tem todo o contexto do código. Por isso o plano traz interfaces e casos de teste exatos, e a implementação segue a spec. Cada tarefa começa pelo teste que falha.

## Global Constraints

- Regras anteriores: sem travessão nem meia risca, pt/en com as mesmas chaves, alvos de 44px, contraste AA nos dois temas (Aurora e Noite), só tokens de cor.
- Nada de rede em tempo de execução além dos arquivos do próprio app.
- Backup: versão 2 lê a versão 1.
- Branch `feat/mvp`. Commits em português, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Ao fim de cada recurso: `npm run check`, `npm test`, `npm run e2e` e `npm run check:dashes` passam. O serviço do celular é atualizado com `npm run build && systemctl --user restart selah-preview`.

## Review Focus

1. **Voz:** pausar e continuar retoma do versículo certo. Parar ou trocar de capítulo no meio de uma fala não dispara a próxima fala (fala "atrasada").
2. **Busca:** "misericordia" acha "misericórdia", e palavras implícitas entre colchetes são encontradas sem os colchetes.
3. **Busca offline incompleta:** mostra o que há e avisa, sem travar.
4. **Migração do banco da versão 1 para a 2:** as leituras, os ajustes e o estado existentes continuam.
5. **Backup:** um arquivo da versão 1 importa sem marcações; uma marcação inválida recusa o arquivo inteiro.

### Task 1: Controlador de voz

**Files:** Create `src/lib/speech.ts`, `src/lib/speech.test.ts`

**Interfaces:**
- `interface SpeechEngine { speak(text: string, rate: number, done: (result: 'end' | 'cancel' | 'error') => void): void; cancel(): void }`
- `type SpeakerState = { status: 'idle' | 'playing' | 'paused'; verse: number | null; rate: number }`
- `createChapterSpeaker(engine: SpeechEngine, onChange: (s: SpeakerState) => void)` returns `{ play(verses: { n: number; text: string }[], from?: number): void; pause(): void; resume(): void; stop(): void; setRate(rate: number): void; state(): SpeakerState }`
- `browserEngine(lang: string): SpeechEngine | null` (null sem `speechSynthesis`)
- `SPEECH_RATES = [0.8, 1, 1.25]`
- `speakable(text: string): string` (tira colchetes)

**Casos de teste (Vitest, motor falso que guarda as falas e deixa o teste chamar `done`):**
1. `play` fala o primeiro versículo e avisa `playing` no versículo 1; `done('end')` passa ao 2; no último, `done('end')` vai para `idle` com `verse: null`.
2. `play(verses, 3)` começa no versículo 3; versículos de texto vazio são pulados.
3. `pause` cancela o motor e fica `paused` no versículo atual; `resume` fala de novo o mesmo versículo.
4. Um `done` atrasado de uma fala cancelada (depois de `pause`, `stop` ou de um novo `play`) não avança nada.
5. `setRate(1.25)` durante a leitura recomeça o versículo atual na nova velocidade.
6. `done('error')` para a leitura (`idle`).
7. `speakable('para [que eu saiba] se')` é `'para que eu saiba se'`.

- [ ] Teste falhando, implementação, teste passando, commit `feat: controlador de leitura em voz alta`.

### Task 3: Núcleo da busca

**Files:** Create `src/lib/search.ts`, `src/lib/search.test.ts`

**Interfaces:**
- `normalize(text: string): string` (minúsculas, sem acentos, sem colchetes, espaços simples)
- `interface IndexedVerse { book: string; chapter: number; verse: number; text: string; norm: string; testament: 'OT' | 'NT' }`
- `buildIndex(books: BookText[]): IndexedVerse[]` (em ordem canônica, pula versículos vazios)
- `searchTerms(query: string): string[]` (normalizados, sem repetidos, só com 2 letras ou mais)
- `searchVerses(index: IndexedVerse[], query: string, opts?: { testament?: 'OT' | 'NT'; limit?: number }): { total: number; results: IndexedVerse[] }`
- `highlightParts(text: string, terms: string[]): { text: string; hit: boolean }[]` (sem colchetes no texto exibido; comparação sem acento)

**Casos:**
1. `normalize('Misericórdia [do] SENHOR')` é `'misericordia do senhor'`.
2. Todas as palavras precisam aparecer, em qualquer ordem; "mundo amou" acha "amou ao mundo".
3. Filtro OT/NT.
4. `limit` corta `results` mas `total` conta tudo.
5. Termos com menos de 2 letras são ignorados; consulta sem termos devolve `total: 0`.
6. `highlightParts('Misericórdia e [paz]', ['misericordia', 'paz'])` destaca "Misericórdia" e "paz", mantendo os acentos originais.
7. Busca por parte da palavra funciona ("miseric" acha "misericórdia").

- [ ] Teste falhando, implementação, teste passando, commit `feat: núcleo da busca por palavra`.
